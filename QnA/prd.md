# PRD: 사내 RAG 챗봇

## 1. 제품 개요

### 1.1 문서 제목 및 버전

- PRD: 사내 RAG 챗봇
- 버전: 1.0

### 1.2 제품 요약

이 문서는 약 100명의 사내 사용자를 위한 윈도우용 데스크톱 챗봇 애플리케이션의 요구사항을 정의한다. 이 챗봇은 분산 컴퓨팅 아키텍처를 기반으로 하며, 중앙 서버는 RAG(Retrieval-Augmented Generation) 시스템의 지식 기반 역할을 하고, 실제 LLM 추론은 각 사용자의 개인 PC에서 수행된다.

이 아키텍처는 회사 보안 정책을 준수하여 모든 데이터 처리 과정을 내부 네트워크에서 완결시킨다. 사용자는 이 챗봇을 통해 내부 문서에 대한 질문을 하고 신속하게 답변을 얻음으로써 업무 생산성을 높일 수 있다.

## 2. 목표

### 2.1 비즈니스 목표

- 신속한 내부 정보 접근을 통해 직원들의 업무 생산성을 20% 향상시킨다.
- 모든 데이터 처리를 사내망으로 제한하여 민감한 내부 정보의 유출을 원천적으로 차단한다.
- 단순 반복적인 질문에 대한 자동 응답으로 내부 지원 부서의 업무 부담을 30% 경감시킨다.
- 기존에 보유한 사용자 PC 자원을 활용하여 LLM 추론을 수행함으로써, 고가의 GPU 서버 인프라 도입 비용을 최소화한다.

### 2.2 사용자 목표

- 업무 관련 질문에 대해 채팅 형태의 인터페이스를 통해 빠르고 정확한 답변을 얻는다.
- 여러 저장소에 흩어져 있는 사내 문서들을 직접 찾지 않고도 필요한 정보를 쉽게 얻는다.
- 복잡한 설치나 설정 과정 없이 챗봇을 편리하게 사용한다.

### 2.3 비목표 (Non-goals)

- 외부 클라우드 기반의 LLM API를 사용하는 것은 고려하지 않는다.
- 웹 기반 인터페이스는 제공하지 않으며, 윈도우 데스크톱 애플리케이션에 집중한다.
- 업무와 무관한 일반적인 대화(雑談) 기능은 포함하지 않는다.
- 실시간 협업 기능은 지원하지 않는다.

## 3. 사용자 페르소나

### 3.1 주요 사용자 유형

- 일반 직원 (영업, 마케팅, 인사 등)
- 기술 직원 (엔지니어, 개발자)
- 시스템 관리자

### 3.2 기본 페르소나 정보

- **일반 직원**: 기술에 익숙하지 않을 수 있으며, 회사 정책, 제품 정보, 프로젝트 이력 등 다양한 내부 정보를 신속하게 찾아야 하는 사용자 그룹이다.
- **기술 직원**: 기술 문서, 코드 예제, 시스템 아키텍처 등 전문적인 정보를 검색하고 업무에 활용해야 하는 사용자 그룹이다.
- **시스템 관리자**: 중앙 서버의 벡터 DB를 관리하고, 챗봇 애플리케이션과 LLM 모델을 배포 및 업데이트하는 책임을 가진다.

### 3.3 역할 기반 접근

- **사용자 (User)**: 애플리케이션을 설치하고 실행하여 질문하고 답변을 받을 수 있다. 정보 접근은 벡터 DB에 저장된 지식으로 제한된다. (일반 직원, 기술 직원 포함)
- **관리자 (Administrator)**: 서버의 벡터 DB와 지식 문서를 관리하고, 챗봇 애플리케이션과 LLM 모델의 새 버전을 배포하며 시스템 상태를 모니터링할 수 있다.

## 4. 기능 요구사항

- **챗 인터페이스** (우선순위: 높음)
  - 사용자는 텍스트 입력 필드를 통해 질문을 입력할 수 있다.
  - 대화 내용은 채팅 형식으로 화면에 표시되어야 한다.
  - 사용자는 챗봇의 답변 텍스트를 복사할 수 있다.
  - 사용자는 현재 대화 내용을 지우고 새로운 대화를 시작할 수 있다.
- **RAG 기반 질의응답** (우선순위: 높음)
  - 애플리케이션은 사용자의 질문을 중앙 벡터 검색 서버로 전송해야 한다.
  - 서버로부터 검색된 관련 지식(문맥)을 수신해야 한다.
  - 로컬 LLM은 사용자의 원본 질문과 수신된 문맥을 함께 사용하여 최종 답변을 생성해야 한다.
- **로컬 LLM 추론** (우선순위: 높음)
  - 애플리케이션은 GGUF와 같이 경량화되고 양자화된 LLM 모델을 포함하거나 관리할 수 있어야 한다.
  - 모든 LLM 추론 과정은 사용자의 로컬 PC에서만 수행되어야 한다.
  - LLM이 답변을 생성하는 동안 사용자에게 '처리 중' 또는 '생각 중'과 같은 시각적 피드백을 제공해야 한다.
- **애플리케이션 자동 업데이트** (우선순위: 중간)
  - 애플리케이션은 시작 시 중앙 관리 시스템을 통해 새 버전의 존재 여부를 확인해야 한다.
  - 새 버전이 있을 경우, 사용자에게 알리고 업데이트를 진행하도록 안내해야 한다.
- **설정 및 정보** (우선순위: 낮음)
  - 사용자는 애플리케이션 및 현재 사용 중인 LLM 모델의 버전을 확인할 수 있어야 한다.
  - 관리자는 중앙 벡터 검색 서버의 주소(IP)를 설정할 수 있는 기능을 제공해야 한다.

## 5. 사용자 경험

### 5.1. 진입점 및 첫 사용자 흐름

- **진입점**: 사용자는 윈도우 바탕화면이나 시작 메뉴의 바로가기를 통해 애플리케이션을 실행한다.
- **첫 사용자 흐름**:
  1. 관리자로부터 설치 파일을 전달받아 실행한다.
  2. 설치 프로그램은 애플리케이션과 LLM 모델을 지정된 경로에 설치한다.
  3. 사용자가 앱을 처음 실행하면, 간결한 채팅창이 나타난다.
  4. "무엇이든 물어보세요"와 같은 안내 문구를 통해 사용자의 첫 질문을 유도한다.

### 5.2. 핵심 경험

- **질문하기**: 사용자는 화면 하단의 입력창에 질문을 타이핑하고 'Enter' 키를 누르거나 '전송' 버튼을 클릭한다.
  - 입력창은 명확하게 보여야 하며 사용하기 쉬워야 한다.
- **답변 대기**: 시스템이 요청을 처리하는 동안, 로딩 애니메이션이나 '답변 생성 중...'과 같은 텍스트를 표시한다.
  - 이를 통해 사용자는 시스템이 멈춘 것이 아니라 정상 동작하고 있음을 인지할 수 있다.
- **답변 확인**: 생성된 답변이 채팅창에 표시된다.
  - 답변은 사용자의 질문과 시각적으로 구분되어야 하며, 목록이나 굵은 글씨체 같은 서식을 지원하여 가독성을 높여야 한다.

### 5.3. 고급 기능 및 예외 처리

- **관련 지식 없음**: 서버에서 질문과 관련된 문서를 찾지 못했을 경우, "죄송합니다, 관련 정보를 찾을 수 없습니다."와 같이 명확한 메시지를 출력해야 한다.
- **네트워크 오류**: 중앙 벡터 검색 서버에 연결할 수 없을 경우, 사용자에게 네트워크 연결 상태를 확인하라는 오류 메시지를 표시해야 한다.
- **저사양 PC**: LLM 추론으로 인해 PC 성능이 저하되더라도, UI는 멈추지 않고 반응성을 유지해야 한다.
- **긴 답변 처리**: 답변의 길이가 길어질 경우, 스크롤 가능한 영역 내에 표시되어야 한다.

### 5.4. UI/UX 하이라이트

- **미니멀리즘 디자인**: 대화에만 집중할 수 있는 깔끔하고 군더더기 없는 인터페이스를 제공한다.
- **즉각적인 피드백**: 로딩 및 처리 상태를 명확하게 시각적으로 보여준다.
- **간편한 사용**: 사내망 접속을 전제로 별도의 로그인 절차 없이 즉시 사용할 수 있도록 한다.
- **뛰어난 가독성**: 질문과 답변을 쉽게 읽을 수 있도록 적절한 글꼴, 크기, 간격을 사용한다.

## 6. 내러티브

마케팅팀의 이민준 대리는 다음 분기 캠페인 기획을 위해 지난 5년간 진행된 모든 캠페인의 성공 지표와 보고서를 찾아야 한다. 이 자료들은 여러 부서의 공유 드라이브와 노션 페이지에 흩어져 있어 찾기가 매우 어렵다. 그는 '사내 RAG 챗봇'을 알게 된다. 챗봇을 실행하고 "지난 5년간 가장 성공적이었던 마케팅 캠페인 3가지와 핵심 성공 요인을 알려줘"라고 질문하자, 챗봇은 즉시 내부 서버의 문서를 검색하고 그의 PC에서 답변을 생성하여 정확한 캠페인 이름, 관련 지표, 그리고 보고서 요약을 정리해서 보여준다. 이민준 대리는 몇 시간 걸렸을 자료 조사를 단 몇 분 만에 끝내고 기획에 더 집중할 수 있게 되었다.

## 7. 성공 지표

### 7.1. 사용자 중심 지표

- 일일 활성 사용자 수 (DAU)
- 사용자 당 평균 질문 수
- 답변 만족도 설문조사 결과 (예: 답변 하단에 '도움이 되었나요?' 버튼)

### 7.2. 비즈니스 지표

- 내부 지원 부서로 인입되는 단순 문의 건수 변화
- 특정 업무(자료 조사 등)에 소요되는 시간 변화 (설문조사를 통해 측정)

### 7.3. 기술 지표

- 평균 답변 생성 시간 (사용자 질문 입력 후 답변 출력까지)
- 서버의 동시 접속자 처리량 및 응답 속도
- 애플리케이션 오류 발생률

## 8. 기술 고려 사항

### 8.1. 통합 지점

- **벡터 검색 서버**: 챗봇 애플리케이션은 REST API 또는 gRPC를 통해 서버와 통신해야 한다.
- **자동 업데이트 서버**: 애플리케이션의 새 버전을 배포하고 관리하기 위한 중앙 서버와의 연동이 필요하다.

### 8.2. 데이터 저장 및 개인정보

- 모든 지식 데이터(벡터 DB)와 대화 내용은 사내 서버 및 개인 PC 내에만 저장된다.
- 사용자 개인 식별 정보는 수집하지 않는다.

### 8.3. 확장성 및 성능

- 벡터 검색 서버는 최소 100명의 동시 요청을 지연 없이 처리할 수 있도록 HNSW와 같은 효율적인 인덱스를 사용해야 한다.
- 로컬 LLM은 일반적인 사무용 PC(CPU 기반)에서도 10초 이내에 답변을 생성할 수 있도록 경량화되어야 한다.

### 8.4. 잠재적 도전 과제

- 다양한 사양의 개인 PC에서 일관된 성능을 보장하는 것.
- 100대에 분산 설치된 애플리케이션과 LLM 모델을 효과적으로 업데이트하고 관리하는 것.
- 벡터 DB에 저장된 지식의 품질과 최신성을 지속적으로 유지하는 것.

## 9. 마일스톤 및 순서

### 9.1. 프로젝트 예상 규모

- 중간(Medium): 3-5주

### 9.2. 팀 규모 및 구성

- 소규모 팀: 총 3-4명

  - 채팅 UI, 서버 통신 클라이언트, 로컬 LLM 연동 등 핵심 기능 구현
  - 주요 결과물: 기본적인 질의응답이 가능한 프로토타입 버전
- **2단계: 안정화 및 배포 준비 (2주)**
  - 예외 처리, 성능 최적화, 자동 업데이트 기능 구현
  - 주요 결과물: 10명 내외의 파일럿 그룹 대상의 베타 버전
- **3단계: 전사 배포 및 고도화 (1주)**
  - 사용자 피드백 반영 및 최종 버전 전사 배포
  - 주요 결과물: 정식 버전 1.0

## 10. 사용자 스토리

### 10.1. 질문하고 답변받기

- **ID**: US-001
- **설명**: 사용자는 업무 관련 질문을 입력하고, 시스템이 제공하는 답변을 확인하고 싶다.
- **인수 조건**:
  - 사용자가 입력창에 텍스트를 입력하고 'Enter' 키를 누르면 질문이 전송된다.
  - 질문이 전송된 후, 답변이 생성될 때까지 '처리 중' 상태가 표시된다.
  - 생성된 답변은 채팅창에 명확하게 표시된다.
  - 네트워크 오류 발생 시, 연결 실패 메시지가 표시된다.

### 10.2. 대화 내용 복사하기

- **ID**: US-002
- **설명**: 사용자는 챗봇의 답변을 다른 문서나 메일에 붙여넣기 위해 텍스트를 복사하고 싶다.
- **인수 조건**:
  - 답변 영역에 '복사' 버튼이 제공된다.
  - '복사' 버튼을 클릭하면 해당 답변의 전체 텍스트가 클립보드에 복사된다.
  - 또는, 사용자가 마우스로 텍스트를 드래그하여 복사(Ctrl+C)할 수 있다.

### 10.3. 새 대화 시작하기

- **ID**: US-003
- **설명**: 사용자는 이전 대화 내용과 무관한 새로운 주제로 질문하기 위해 현재 대화창을 초기화하고 싶다.
- **인수 조건**:
  - '새 대화' 또는 '초기화' 버튼이 제공된다.
  - 해당 버튼을 클릭하면 기존 대화 내용이 모두 삭제되고 초기 상태로 돌아간다.

### 10.4. 애플리케이션 자동 업데이트

- **ID**: US-004
- **설명**: 시스템 관리자는 모든 사용자가 항상 최신 버전의 챗봇을 사용하도록 중앙에서 업데이트를 배포하고 싶다.
- **인수 조건**:
  - 애플리케이션 시작 시, 업데이트 서버에서 최신 버전 정보를 확인한다.
  - 새로운 버전이 있을 경우, 사용자에게 알림 팝업이 표시된다.
  - 사용자가 '업데이트' 버튼을 클릭하면 설치가 진행되고 애플리케이션이 재시작된다.

### 10.5. 시스템 관리 및 설정

- **ID**: US-005
- **설명**: 시스템 관리자는 문제 해결 및 관리를 위해 벡터 검색 서버의 주소를 변경하고 싶다.
- **인수 조건**:
  - 관리자만 접근할 수 있는 설정 화면 또는 설정 파일을 제공한다.
  - 해당 설정에서 서버의 IP 주소와 포트 번호를 수정하고 저장할 수 있다.
  - 애플리케이션 재시작 시, 변경된 서버 주소로 연결을 시도한다.
