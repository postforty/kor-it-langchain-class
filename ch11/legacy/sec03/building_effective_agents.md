# Building effective agents

> Building effective agents 공식 문서: <https://www.anthropic.com/engineering/building-effective-agents>

## 에이전트의 정의 및 원칙

- **에이전트와 워크플로우의 구분**: `워크플로우`는 <u>미리 정의된 코드를 기반으로 특정 작업을 자동화</u>하지만, `에이전트`는 LLM(대규모 언어 모델)이 <u>동적으로 자체 프로세스를 관리하며 도구 사용을 지시</u>한다. 즉, 에이전트는 워크플로우보다 더 높은 수준의 자율성을 가진다.
- **핵심 원칙**: 에이전트 설계는 **단순성**(Simplicity)을 유지하는 것이 중요하며, 에이전트의 계획 단계를 명시적으로 보여주어 **투명성**(Transparency)을 우선시해야 한다. 또한, 도구 문서화와 테스트를 철저히 하여 **에이전트-컴퓨터 인터페이스**(ACI)를 세심하게 제작해야 한다.

## 에이전트의 작동 방식

- **계획 및 실행**: 에이전트는 사용자와의 명확한 소통을 통해 작업을 파악한 후, 독립적으로 계획을 수립하고 작업을 실행한다.
- **피드백 루프**: 각 단계에서 도구 호출 결과나 코드 실행 결과와 같은 **실측 자료**(ground truth)를 확보하여 진행 상황을 평가한다. 이 과정을 통해 에이전트는 목표를 달성할 때까지 반복적으로 피드백 루프를 수행한다.
- **도구 사용**: 에이전트는 외부 자원(예: 검색 엔진)을 활용하기 위해 도구를 사용한다. 에이전트가 도구를 효과적으로 사용하도록 하려면, 도구의 명칭과 매개변수를 모델이 명확하게 이해할 수 있도록 정의하고 예시를 포함하는 것이 중요하다.

## 효과적인 에이전트 구축 방법론

- **모델 관점 이해**: 에이전트가 도구를 어떻게 사용할지 모델의 관점에서 생각하고, 도구 설명과 매개변수 이름을 명확하게 작성해야 한다.
- **철저한 테스트**: 모델이 도구를 어떻게 사용하는지 다양한 예시 입력으로 테스트하고, 실수를 줄이도록 매개변수나 인터페이스를 수정해야 한다.
- **프롬프트 엔지니어링**: 에이전트가 복잡한 작업을 효율적으로 처리하도록 프롬프트에 명시적인 지침을 포함하여 작업량을 조절할 수 있도록 한다. 예를 들어, 단순한 정보 검색에는 적은 수의 도구 호출을, 복잡한 연구에는 여러 하위 에이전트를 할당하도록 지시하는 방식이다.
