# Human-in-the-Loop
Human-in-the-Loop는 다양한 업무 시나리오에서 효과적으로 활용될 수 있습니다.

| 시나리오 | 설명 |
| --- | --- |
| 이메일 자동 발송 | AI가 이메일 초안을 작성 → 사람이 검토 후 발송 승인 |
| 데이터 삭제 작업 | 중요 데이터 삭제 전에 관리자 승인 필수 |
| 문서 생성 및 배포 | AI가 문서를 생성 → 담당자가 검토·수정 후 최종 배포 |
| 금융 거래 처리 | 고액 거래나 위험 거래 시 담당자의 최종 승인 필요 |

## ⚠️ 인터럽트 사용 시 주의사항 (Rules of Interrupts)

LangGraph에서 `interrupt`를 실무에 적용할 때 반드시 알아야 할 핵심 원칙입니다.

1. **노드 재실행 및 멱등성 (Idempotency)**
   - `interrupt`로 멈췄던 그래프가 사용자의 응답으로 재개(resume)되면, 멈췄던 줄에서 이어지는 것이 아니라 **해당 노드의 처음부터 다시 실행**됩니다.
   - 따라서 `interrupt` 호출 이전에 데이터베이스 저장이나 API 호출 같은 부수 효과(Side effect)를 일으키는 코드가 있다면 중복 실행될 위험이 있으므로, 가급적 인터럽트 이후에 배치하거나 멱등성을 갖도록 설계해야 합니다.

2. **예외 처리(`try/except`) 주의**
   - `interrupt`는 내부적으로 특수한 예외(Exception)를 발생시켜 실행을 중지시킵니다.
   - 만약 `interrupt()` 호출을 포괄적인 `try/except Exception:` 블록으로 감싸게 되면, 시스템이 예외를 가로채어 중단 기능이 오작동할 수 있습니다.

3. **`invoke()` vs `stream_events()`**
   - 본 챕터의 예제들은 학습의 직관성을 위해 기본 API인 `invoke()`를 사용합니다 (`result["__interrupt__"]` 형태로 반환).
   - 하지만 프로덕션 환경에서 인터럽트 가능한 그래프를 구동할 때는 이벤트 스트리밍 방식인 `stream_events(..., version="v3")`를 사용하여 상태를 제어하는 것이 공식적으로 권장됩니다.
